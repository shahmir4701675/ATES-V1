# ATES working context

- Scope work to the requested batch. Do not rebuild the app or start the next batch automatically.
- FastAPI/SQLAlchemy backend: `backend/main.py`, authenticated routers, adapter, immutable snapshot services.
- Real solvers: CP-SAT timetable; NetworkX DSATUR + CP-SAT exam fallback. Independent validators gate persistence.
- Generation: `backend/generation.py` supervises spawned processes; `backend/generation_execution.py` runs generation without importing/building HTTP routers; `engine/execution.py` shares one monotonic budget. Durable run ownership/state/lease and commit fencing gate saves; never replace these with polling-only cancellation.
- Package exports of the FastAPI app/helpers and seed function are lazy in `backend/__init__.py`. Never eagerly import `backend.main` there: every spawned job would construct the whole web/export stack inside its deadline. The isolated import-boundary test preserves public exports without loading HTTP routers in workers.
- Existing installations require reviewed additive migrations 001 through 005 (operator-selected database only). Migration 004 adds persisted CSV staging; 005 adds exam override flags, append-only edit history/log guards, FK indexes and snapshot-aware exam capacity checks. Apply 005 once, inside its transaction; do not run it against an already upgraded schema. Worker generation requires file-backed SQLite or PostgreSQL and a spawn-compatible server entrypoint.
- Startup initializes the default session factory before recovery. Live leases are preserved; expired runs are reaped every second after a 15-second lease grace.
- S05 receives full previous timetable separately from mandatory locks. Include previous inputs in freshness checks and immutable snapshots.
- Accounts/audit: `backend/routers/accounts.py`; own-password changes in `routers/auth.py`. Password/role/status/link changes revoke sessions; passwords never appear in responses or audit details. Accounts are deactivated, never deleted by an API.
- Schedule reads/exports share `backend/schedule_access.py`: Coordinator/Approver review history; other roles require Published status; Faculty/Students are limited by trusted instructor/batch links. Use frozen display references, not current master data, for history.
- Publication/archive are Approver-only transactions. A new publication requires an existing trusted snapshot, independent validation and current input equality. Archive the previous Published version under the common input lock. Never auto-create a legacy snapshot through a publication request.
- CSV: `csv_imports.py` and `routers/imports.py`, six templates/types, UTF-8 and 10 MB limit. Owner-scoped previews persist for one hour; confirmation revalidates under the input lock and commits rows, counts, history and audit atomically. Never accept client-submitted validated rows.
- Downloads: `schedule_exports.py` / `routers/exports.py`; authenticated CSV/PDF with frozen metadata, server-side filters and audit. ReportLab creates PDFs; pypdf inspects test output. Render representative PDFs with `pdftoppm` after layout changes.
- Preserve B001 bearer/session/RBAC; B002 physical interval/grid checks; B003 enrollment oracle; B005 lab continuity.
- B004 snapshots/receipts are immutable. Historical views use original inputs. Legacy recovery and PostgreSQL execution remain incomplete.
- Generated-only adjustments use `backend/manual_edits.py`: move whole lab blocks, validate independently against frozen inputs, persist overrides/locks, append checksummed output revisions. New generation captures revision zero atomically; older versions capture their first tracked pre-edit state. Undo restores that baseline, not inferred pre-upgrade history. Frontend sends `expected_revision`; reject stale or out-of-band output changes.
- Verified authentication stamps the request session actor. `mutation_audit.py` records source CRUD in the same transaction; explicit workflow logs cover accounts/imports/publication/exports/generation/adjustments. Logs and edit history are append-only in both dialects. Never log secrets or disable DB guards.
- Acquire the common input-state lock before config selection and schedule version allocation. Retain freshness, independent validation and cancellation commit fences. Translate lock/serialization conflicts to controlled responses; do not overwrite a competing version.
- Configurations: Coordinator-only deletion is persistent and allowed only when no schedule references the configuration. Delete/check/generate share the input lock. Save solver settings and rules in one PUT; defaults are filled on creation and persisted rules are validated before queueing. Never hide deleted IDs in browser memory.
- UI: `components/TimetableGrid.tsx` stacks parallel sessions in physical day/slot cells. `locales/index.ts` treats naive server timestamps as UTC and formats Asia/Karachi; clock windows remain frozen original values. English/help resources and public guides live in `frontend/src/locales` and `frontend/public/help`; complete dynamic-string extraction and browser acceptance remain tracked.
- Use only explicit disposable SQLite databases for tests/migrations. Never load production credentials or migrate/seed an existing user database.
- Keep mandatory hard constraints and existing test assertions. Adapt fixtures only when an intentional API/schema contract changes.
- Read `audit_reports/PROGRESS.md` and `REMAINING_WORK.md` before work. Consult specific SRS sections rather than re-extracting the whole PDF.
