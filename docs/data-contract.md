# ATES Data Contract

This document defines the canonical data contract for the **Auto Timetable / Exam Scheduler (ATES)** based on `docs/SRS.pdf` (Section 3, Section 5, and Appendix A). All layers—PostgreSQL/Supabase database, FastAPI REST endpoints, OR-Tools/NetworkX scheduling engine, React front end, and CSV import/export modules—must adhere strictly to these field definitions, types, and constraints.

---

## 1. Conventions & System Constants

### 1.1 Naming & Formatting Conventions (SRS Section 1.5.3, DB-3, DB-8)
- **Database Tables**: Lowercase plural `snake_case` (21 tables total).
- **Primary Keys**: Single-column integer surrogate key named `<entity>_id` (`GENERATED BY DEFAULT AS IDENTITY`).
- **JSON API Payloads**: UTF-8 JSON using the exact `snake_case` field names defined below.
- **Time & Date Formats**:
  - **Time**: 24-hour format `HH:MM` (or `HH:MM:SS` in SQL `TIME`).
  - **Date**: ISO-8601 `YYYY-MM-DD` in API/DB; rendered as `DD/MM/YYYY` in the UI.
  - **Timestamps**: Stored in UTC (`TIMESTAMP` / `TIMESTAMPTZ`) and displayed in local time (`Asia/Karachi`, UTC+05:00).
- **Domain Identifiers**:
  - Course code format: e.g., `CS-326`
  - Student seat number / identifier format: e.g., `CS-24145`

## 3. Courses, Offerings & Enrollments

### 3.1 Courses (`courses` — SRS 5.1.3.5, FR-2.1, FR-2.2)
Course catalogue entries.

| Field | SQL Type | JSON Type | Nullable | Default | Constraints & Validation Rules |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `course_id` | `INTEGER` | `number` | `NOT NULL` | Auto-increment | Primary Key |
| `course_code` | `VARCHAR(15)` | `string` | `NOT NULL` | — | `UNIQUE` (e.g., `CS-326`) |
| `title` | `VARCHAR(150)` | `string` | `NOT NULL` | — | Course title |
| `department_id` | `INTEGER` | `number` | `NOT NULL` | — | `FK -> departments(department_id)` |
| `credit_hours` | `SMALLINT` | `number` | `NOT NULL` | — | `CHECK (credit_hours >= 0)` |
| `lecture_hours` | `SMALLINT` | `number` | `NOT NULL` | `0` | `CHECK (lecture_hours >= 0)` (weekly lecture contact hours) |
| `lab_hours` | `SMALLINT` | `number` | `NOT NULL` | `0` | `CHECK (lab_hours >= 0)` (weekly lab contact hours) |
| `is_active` | `BOOLEAN` | `boolean` | `NOT NULL` | `true` | Soft deactivation flag (FR-2.11) |

- **Table Constraint**: `CHECK (lecture_hours + lab_hours > 0)` (FR-2.2).
- **Session & Lab Block Derivation Rule (FR-2.9, H08, H09)**:
  Given term slot length $L_{\text{slot}}$ (minutes, default `60`):
  - **Lecture sessions per week**: $N_{\text{lecture}} = \lceil (\text{lecture\_hours} \times 60) / L_{\text{slot}} \rceil$, where each lecture session occupies **1 slot**.
  - **Lab blocks per week**: If $\text{lab\_hours} > 0$, 1 contiguous lab block per week occupying $k = \lceil (\text{lab\_hours} \times 60) / L_{\text{slot}} \rceil$ **consecutive slots on the same day in the same Lab room** (stored as $k$ rows in `timetable_entries` with `session_type = 'Lab'`). If $\text{lab\_hours} = 0$, 0 lab blocks.

### 3.2 Course Offerings (`course_offerings` — SRS 5.1.3.10, FR-2.8, FR-2.9)
A course taught to one student batch by one instructor in one academic term (the schedulable unit).

| Field | SQL Type | JSON Type | Nullable | Default | Constraints & Validation Rules |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `offering_id` | `INTEGER` | `number` | `NOT NULL` | Auto-increment | Primary Key |
| `term_id` | `INTEGER` | `number` | `NOT NULL` | — | `FK -> academic_terms(term_id)` |
| `course_id` | `INTEGER` | `number` | `NOT NULL` | — | `FK -> courses(course_id)` |
| `batch_id` | `INTEGER` | `number` | `NOT NULL` | — | `FK -> batches(batch_id)` |
| `instructor_id` | `INTEGER` | `number` | `NOT NULL` | — | `FK -> instructors(instructor_id)` |
| `enrolled_count` | `SMALLINT` | `number` | `NOT NULL` | — | `CHECK (enrolled_count > 0)` |

- **Table Constraint**: `UNIQUE (term_id, course_id, batch_id)` (FR-2.8: rejects a second offering of the same course to the same batch in the same term).

### 3.3 Student Enrollments (`enrollments` — SRS 5.1.3.11, FR-2.10, A-4)
Optional individual student-to-offering links used to detect exam clashes for electives and repeaters. When no individual enrollment records exist for an offering, students of the offering's `batch_id` are assumed to take every course offered to their batch (Assumption A-4).

| Field | SQL Type | JSON Type | Nullable | Default | Constraints & Validation Rules |
| :--- | :--- | :--- | :--- | :--- | :--- |

| `student_id` | `INTEGER` | `number` | `NOT NULL` | — | `FK -> users(user_id)` (must have `role = 'Student'`) |

- **Table Constraint**: `UNIQUE (offering_id, student_id)`.

## 5. Rooms (`rooms` — SRS 5.1.3.8, FR-2.4)

Lecture rooms, laboratories, and examination halls.

| Field | SQL Type | JSON Type | Nullable | Default | Constraints & Validation Rules |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `room_id` | `INTEGER` | `number` | `NOT NULL` | Auto-increment | Primary Key |
| `room_code` | `VARCHAR(20)` | `string` | `NOT NULL` | — | `UNIQUE` (e.g., `Rm 301`, `Lab 2`) |
| `building` | `VARCHAR(50)` | `string` | `NOT NULL` | — | Building name/identifier (used by `ES03`) |
| `capacity` | `SMALLINT` | `number` | `NOT NULL` | — | `CHECK (capacity > 0)` |
| `room_type` | `VARCHAR(12)` | `string` | `NOT NULL` | — | `CHECK (room_type IN ('Lecture', 'Lab', 'Exam Hall'))` |
| `is_active` | `BOOLEAN` | `boolean` | `NOT NULL` | `true` | Soft deactivation flag (FR-2.11) |

- **Room Eligibility Rules**:
  - **Timetable (`H05`)**: `session_type = 'Lecture'` requires `room_type = 'Lecture'`; `session_type = 'Lab'` requires `room_type = 'Lab'`.
  - **Exam Schedule (`FR-7.4`, `E03`, `E04`)**: Exams are allocated to active rooms with `room_type IN ('Exam Hall', 'Lecture')` (excluding `'Lab'` rooms), prioritizing `'Exam Hall'` first and minimizing the number of rooms (`ES02`) and keeping rooms in the same building (`ES03`).

### 8.3 Complete Constraint Catalogue (SRS Appendix A.5, FR-5.1, FR-5.2)

#### Timetable Constraints (`schedule_type = 'Timetable'`)

| `rule_code` | `rule_type` | Mandatory (FR-5.2) | Seeded `weight` | Default `param_value` | Rule Definition |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `H01` | `Hard` | **Yes** | `0` | `NULL` | An instructor teaches at most one session in a slot. |
| `H02` | `Hard` | **Yes** | `0` | `NULL` | A room hosts at most one session in a slot. |
| `H03` | `Hard` | **Yes** | `0` | `NULL` | A batch attends at most one session in a slot. |
| `H04` | `Hard` | No | `0` | `NULL` | Room capacity is at least the `enrolled_count` of the offering. |
| `H05` | `Hard` | No | `0` | `NULL` | Lab sessions are held in `Lab` rooms and lectures in `Lecture` rooms. |
| `H06` | `Hard` | No | `0` | `NULL` | No session in a slot in which the instructor is unavailable (`is_available = false`). |
| `H07` | `Hard` | No | `0` | `NULL` | No session in a blocked slot (`is_blocked = true`). |
| `H08` | `Hard` | **Yes** | `0` | `NULL` | Every offering receives exactly the number of lecture sessions and lab blocks required per week. |
| `H09` | `Hard` | No | `0` | `NULL` | A lab block occupies consecutive slots of one day in one room. |
| `H10` | `Hard` | No | `0` | `NULL` | An instructor does not exceed `max_daily_hours` and `max_weekly_hours`. |
| `S01` | `Soft` | No | `5` | `NULL` | Minimise idle gaps between the sessions of a batch on a day. |
| `S02` | `Soft` | No | `5` | `NULL` | Spread the sessions of one offering over different days. |
| `S03` | `Soft` | No | `5` | `5` | Keep the number of sessions of a batch per day at or below `param_value`. |
| `S04` | `Soft` | No | `5` | `3` | Keep consecutive teaching slots of an instructor at or below `param_value`. |
| `S05` | `Soft` | No | `5` | `NULL` | Prefer the same slot and room as in the previous version (stability). |
| `S06` | `Soft` | No | `5` | `NULL` | Prefer the smallest room that fits the offering. |

#### Exam Schedule Constraints (`schedule_type = 'Exam'`)

| `rule_code` | `rule_type` | Mandatory (FR-5.2) | Seeded `weight` | Default `param_value` | Rule Definition |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `E01` | `Hard` | **Yes** | `0` | `NULL` | Two courses that share at least one student are not in the same exam session. |
| `E02` | `Hard` | No | `0` | `2` | No student has more exams per day than `param_value`. |
| `E03` | `Hard` | No | `0` | `NULL` | Allocated seats equal `student_count` and never exceed room capacity. |
| `E04` | `Hard` | **Yes** | `0` | `NULL` | A room is used by at most one exam in a session. |
| `E05` | `Hard` | **Yes** | `0` | `NULL` | Every course with an exam is assigned to exactly one session. |
| `ES01` | `Soft` | No | `5` | `NULL` | Spread the exams of one batch over different days. |
| `ES02` | `Soft` | No | `5` | `NULL` | Use as few rooms as possible per exam. |
| `ES03` | `Soft` | No | `5` | `NULL` | Keep the rooms of one exam in the same building. |

- **Table Constraints**:
  - `UNIQUE (term_id, schedule_type, version_no)`
  - At most one `'Published'` schedule per `(term_id, schedule_type)` (FR-9.3). Publishing a new version automatically transitions the previously `'Published'` version to `'Archived'`.

## 10. CSV Import & Export Contracts

### 10.1 Bulk CSV Import Templates (FR-4.1 to FR-4.4)
All CSV imports use UTF-8 encoding (max 10 MB) and reference related records via natural keys, which the server resolves to foreign key IDs during row-level validation:

| Import Type (`/import/{type}`) | Exact CSV Header Columns |
| :--- | :--- |
| `courses` | `course_code,title,department_code,credit_hours,lecture_hours,lab_hours` |
| `instructors` | `full_name,email,department_code,max_daily_hours,max_weekly_hours` |
| `rooms` | `room_code,building,capacity,room_type` |
| `batches` | `program_code,batch_year,section,department_code,strength` |
| `offerings` | `term_name,course_code,program_code,batch_year,section,instructor_email,enrolled_count` |
| `enrollments` | `term_name,course_code,program_code,batch_year,section,student_username` |

**Validation Report Payload (`POST /import/{type}`)**:
```json
{
  "entity_type": "courses",
  "file_name": "courses_fall2026.csv",
  "rows_total": 42,
  "rows_valid": 40,
  "rows_rejected": 2,
  "rejected": [
    {
      "line_number": 14,
      "column": "lecture_hours",
      "reason": "Total weekly contact hours (lecture_hours + lab_hours) must be greater than 0 (FR-2.2)."
    }
  ]
}
```

### 10.2 Schedule CSV Export Contract (FR-11.2)
`GET /schedules/{id}/export?format=csv` returns a UTF-8 CSV file with one row per scheduled session or exam and the exact columns required by FR-11.2:
```csv
day,start_time,end_time,course_code,session_type,instructor,room,batch
Monday,08:00,09:00,CS-326,Lecture,Dr. Fakhra Aftab,Rm 301,BSCS-2024-A
```
*(For exam schedules, `day` contains the `exam_date` `DD/MM/YYYY`, `session_type` contains `'Exam'` or the session `label`, `room` contains the allocated room code(s), and `batch` contains the associated batch code(s).)*
